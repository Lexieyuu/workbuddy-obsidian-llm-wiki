# LLM Wiki 知识库健康检查

把 Wiki 当作一个需要静态检查的知识图谱，发现结构问题和认知技术债。

## 工作流程

1. 定位当前 Vault 根目录，只检查 `wiki/`，不读取 `raw/09-archive/`。
2. 读取 `wiki/index.md`，提取其中的 `[[页面名称]]`。
3. 扫描 `wiki/` 下所有 Markdown 文件，排除 `index.md` 和 `log.md`。
4. 检查索引一致性：文件存在但未登记，或索引登记但目标不存在。
5. 扫描所有 Wiki 页面中的 `[[双链]]`；目标不存在的标为死链。
6. 统计页面被其他页面引用的次数；从未被引用的页面标为孤儿页面，排除自引用。
7. 搜索 `## 知识冲突`，统计未解决冲突。

## 输出格式

```markdown
## 🩺 知识库健康体检报告 — YYYY-MM-DD

### ✅ 绿灯项
- [运行良好的项目]

### ⚠️ 黄灯项
- **发现 N 个孤儿页面**：[列表]
- **发现 N 个未同步索引**：[列表]

### ❌ 红灯项
- **发现 N 个死链**：[来源页面] → [[不存在的目标页面]]
- **存在 N 个未解决的知识冲突**：[页面名称]

### 🛠️ 下一步行动
1. 是否需要修复未同步索引？
2. 是否需要处理知识冲突？
```

## 硬约束

- 本 Skill 只读扫描，生成报告前禁止修改、删除或重命名任何文件。
- 报告后等待用户确认，再执行任何修复。
- 修复完成后才可在 `wiki/log.md` 追加 `lint` 日志。
